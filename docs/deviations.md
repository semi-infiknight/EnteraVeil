## Phase 1 — Solace baseline

- **Cloned `rigby-sh/solace-medusa-starter-api` into `apps/medusa/`** (storefront already in place from Phase 0). Removed its embedded `.git` so it merges into monorepo.
- **Local runtime unavailable**: Docker Desktop is NOT installed on this Windows machine (`docker`/`psql`/`redis-server` all missing); pnpm was missing and I installed it via `npm i -g pnpm@10`. Therefore the plan's `docker compose up -d`, `pnpm medusa db:migrate`, `pnpm seed`, admin user creation, publishable-key auto-fetch, and `pnpm dev` smoke test **cannot run in this environment**. All these steps are deferred until the user installs Docker Desktop. The configuration files (docker-compose.yml, .env files, scripts) are still authored per plan so they will work once Docker is up.
- **Skipped `pnpm install`** at this point: the Medusa starter uses yarn (presence of `yarn.lock` + `.yarnrc.yml`), and installing through pnpm in the workspace would either need overrides or risk corrupting native build deps. Will be done by user after Docker comes up; documented in Phase 1 README addendum.
- **Publishable key autofetch deferred to runtime**: the SQL query approach is preserved in `scripts/fetch-publishable-key.sh` so user can run it once Postgres is reachable.

## Phase 2 — EnteraVeil brand identity

- **Logo as text wordmark, not raster**: Plan said create `src/components/logo.tsx` rendering `<span className="font-heading">EnteraVeil</span>`. I created that file AND, separately, replaced the bodies of the existing icon-based logo components (`SolaceLogo`/`SolaceLogoBig`) with SVG `<text>` elements that render "EnteraVeil" in Space Grotesk via `var(--font-heading)`. Renamed the symbols to `Wordmark` / `WordmarkBig` and the files to `wordmark.tsx` / `wordmark-big.tsx`. Reason: every nav/footer/banner consumer was already wired to the SVG component pattern with `className="h-6"` sizing — swapping internals + renaming avoided changing the layout of a dozen call sites while making the symbol names brand-neutral.
- **Tailwind brand color variables (CSS-var pattern, not hard-coded `tailwind.config.ts` colors)**: PLAN said update `apps/storefront/tailwind.config.ts` with brand colors. The actual file is `tailwind.config.js` and brand tokens already live in `preset/plugins/colors.js` as `--bg-*` / `--content-*` / `--border-*` CSS variables consumed via `rgb(var(--token) / <alpha-value>)`. I updated that file directly so existing components using `text-action-primary`/`border-action-primary-hover`/etc. inherit the new accent — gold (#FFB627) / deep-amber (#E8801A). Also normalized BG to PROJECT_CONFIG's #0A0A0A and danger color to #EF4444.
- **Fonts wired as CSS variables on `<html>`**: `next/font/google` for Space Grotesk + Inter, exposed as `--font-heading` and `--font-body`, then `fontFamily.heading` / `fontFamily.body` registered in `preset/theme/typography.js`. Replaces the old fixed-Inter `sans` family. The SVG wordmark components use `var(--font-heading)` directly so they pick up the same family.
- **Default theme = dark**: `next-themes` `defaultTheme="dark"` in `app/layout.tsx`. Light toggle kept (enableSystem still on).
- **Added missing deps `clsx` + 4 Radix packages** (`@radix-ui/react-checkbox`, `@radix-ui/react-dialog`, `@radix-ui/react-radio-group`, `@radix-ui/react-tabs`). Reason: the Solace baseline imports these modules across `src/lib/util/cn.ts` and several common components, but they weren't in `package.json` (likely relied on a hoisted yarn install behavior). Without them `pnpm typecheck` errored out before Phase 2 ever ran. Added so the verify step can actually pass. No version pinning since these are leaf utility libs.
- **Storefront installed via pnpm** (not yarn): The plan's Phase 1 deviation noted yarn-vs-pnpm risk; in practice `pnpm install` ran cleanly. Kept `apps/storefront/package-lock.json` and `apps/medusa/yarn.lock` in place — they don't get used by pnpm and removing them is a separate cleanup.
- **Banner SVG sizing preserved**: `WordmarkBig` keeps the original 1329×234 viewBox so the home-page banner consumer (`modules/content/components/banner/index.tsx`) doesn't change its `h-auto w-full` layout. The text is centered with `textAnchor="middle"` at the viewBox midpoint.
- **`icon.tsx` and `opengraph-image.tsx`** created with `ImageResponse` from `next/og`. Plain inline styles (no Tailwind) because `ImageResponse` doesn't support Tailwind classes at render time. System font fallback used in OG because Space Grotesk would require font bytes to be loaded inline — not worth the complexity for an OG image; the gold accent + dark BG carries the brand.
- **Skipped renaming `apps/storefront/package.json` name `"solace-medusa-starter"`**: technical identifier per PLAN's Phase 2 rule "Leave technical identifiers (package names, npm scripts) untouched." Same for `README.md` and the `apps/medusa/LICENSE` upstream attribution.
